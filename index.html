End-to-End Attack Chains in Agentic CI Systems

C1

Resource Amplification

Target: [masked] · 100k+ ★ dev-tool repo Entry: external issue (allow-users: "*") Impact: 1 issue → 2–3 paid model sessions + label-injection DoS
  1. Normal behavior. Two workflows (issue-labeler, issue-deduplicator) invoke a coding agent for every issue, regardless of author privileges.
  2. Attack. An unprivileged external account files a single issue embedding task-disguise (L1) instructions.
  3. Propagation. Both workflows fire in parallel; the deduplicator runs a second model pass when no match is found.
  4. Impact. Multiple billable agent sessions per issue, plus injected labels suppressing triage decisions entirely.
C2

Automated Decision Manipulation

Target: [masked] · mobile-dev repo Entry: forged support-ticket text in an external issue Impact: agent labels, closes, and posts fake official confirmation
  1. Normal behavior. A maintainer runs @claude re-triage on an issue; the agent classifies and a nightly workflow later acts on the verdict.
  2. Attack. An external account embeds a forged internal ticket ("approved by the security team", canary-marked) in the issue body.
  3. Propagation. The maintainer's routine re-triage makes the agent read the attacker's text as the decision basis; the verdict flows to the deterministic sweep workflow via labels and marked comments.
  4. Impact. Priority inflation, wrongful auto-close as "completed"/"not planned", and a bot-posted fake confirmation citing the fabricated ticket.
C3

Privileged Repository Modification

Target: [masked] · desktop-app repo (public advisory) Entry: PR review comment containing a trigger word Impact: attacker content committed under the project bot identity
  1. Normal behavior. An auto-fix workflow hands PR review comments containing claude-fix to an agent with contents: write.
  2. Attack. The workflow checks only the commenter's account type (User), not repository write permission — any external account qualifies.
  3. Propagation. The agent treats the comment body as "the user's primary request" and executes allowed git add/commit/push.
  4. Impact. The requested content is persistently committed to the PR branch under claude[bot]; maintainers later removed the workflow and published an advisory.
C4

Protected Information Exfiltration

Target: [masked] · 10k+ ★ developer-tool repo Entry: issue requesting bug reproduction with a "community helper" Impact: arbitrary package execution inherits and exfiltrates runtime credentials
  1. Normal behavior. The issue-intake agent is expected to reproduce reported bugs; its bash policy permits npx * / npm *.
  2. Attack. An external issue asks the agent to run an attacker-controlled helper package as part of reproduction.
  3. Propagation. The package process inherits the step environment, including model API keys and the bot's GitHub token.
  4. Impact. Credential digests arrive at the attacker-observable collection endpoint; maintainers fixed it by removing shell access and isolating the token.

Ethics & Anonymization

All demonstrations were conducted in researcher-controlled repository copies, using dedicated test accounts and synthetic canary credentials. We did not execute attacks against the original repositories or modify their workflows.

All affected repositories were responsibly disclosed through their designated security channels; several have published security advisories and CVE requests. Repository identities, owners, and account names are masked in the videos above.

We use synthetic canary markers instead of real credentials; no real user data appears in any demo.
